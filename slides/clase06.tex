\begin{frame}{Mini diagnóstico: vote antes de discutir}
\small
Marque \textbf{V} o \textbf{F}. No busque todavía la respuesta perfecta: identifique qué palabra de cada frase le genera desconfianza.
\begin{enumerate}
\item Si \texttt{COMMIT} respondió, la página de la tabla ya está necesariamente en el SSD.
\item Si el dato está en tres memorias RAM, entonces es durable.
\item MVCC evita toda anomalía de concurrencia.
\item Un índice siempre mejora el rendimiento global.
\item Una LSM-tree elimina el costo de escribir.
\end{enumerate}
\begin{alertblock}{Volveremos al final}
La clase será buena si puede refutar o defender cada afirmación con un mecanismo, una falla y una métrica.
\end{alertblock}
\end{frame}

\begin{frame}{Volvemos al diagnóstico inicial}
\begin{enumerate}
\item \textbf{Falso:} el commit puede ser durable aunque la página siga atrasada.
\item \textbf{Falso:} copiar en RAM no equivale a persistir.
\item \textbf{Falso:} MVCC reduce contención, pero no elimina todas las anomalías.
\item \textbf{Falso:} un índice puede no usarse y siempre cuesta mantenerlo.
\item \textbf{Falso:} una LSM desplaza trabajo hacia flush y compaction.
\end{enumerate}
\begin{block}{Patrón común}
Ningún mecanismo elimina costo: cambia \emph{cuándo}, \emph{dónde} y \emph{cómo} se paga.
\end{block}
\end{frame}
